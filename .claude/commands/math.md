## Принцип

Мат-модель — НЕ «детальный бриф простыми словами», а **формальный документ для ИИ**. Цель — однозначность. Бриф читает человек, мат-модель читает ИИ.

## Прочитай

1. `PROJECT_BRIEF.md`
2. `docs/examples/EXAMPLE_MATH_MODEL.md` — образец стиля. Делай в таком формате.

## Правила формализации

- **Типы и множества:** `E ∈ [0,100]`, `status ∈ {confirmed, cancelled}`, `id: UUID`
- **Сквозная нумерация §N.M** обязательно
- **Cross-references:** «согласно §4.2», «нарушает I3»
- **Инварианты с именами** I1, I2, ... : `I1: ∀ a1,a2 ∈ X, ... → ...`
- **Формулы F1, F2, ...** с примерами с числами
- **Lifecycle** — таблицей переходов с trigger/guard/side-effects
- **Операции** с pre-условиями, post-условиями, errors
- **Короткий комментарий** на человеческом языке: `// бизнес-смысл: ...`
- **Открытые вопросы** с приоритетом: 🔴 BLOCKER / 🟡 NEEDED / 🟢 LATER

## Алгоритм работы

1. **Спрашивай бизнес-языком, записывай формально.** «Может клиент записаться дважды на одно время?» → «I3: ∀ a1,a2 ∈ Appointment, ... → ...»

2. **Вопросы блоками по 2-3**, не больше. Используй AskUserQuestion. Показывай результат и жди подтверждения.

3. **Если не знает** — предлагай дефолт с обоснованием. Технические дефолты (HTTPS, bcrypt, бэкапы) — принимай сам.

4. **WebSearch** для отраслевой специфики если бриф этого не покрыл.

5. **Веди глоссарий:** один термин → одно понятие → один тип.
