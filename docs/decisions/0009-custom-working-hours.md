# Упрощение настройки рабочих часов и поведение деактивированных мастеров

## Context and Problem Statement

Необходимо упростить интерактивную настройку рабочих часов мастеров в панели администратора, предоставив ровно три понятные опции для каждого дня недели вместо четырех фиксированных диапазонов.
Также требуется автоматизировать обработку рабочего статуса мастера: если мастер деактивирован, его рабочие часы для всех внешних систем (вывод расписания, расчет свободных слотов, проверка записей) должны автоматически трактоваться как выходные. При повторной активации исходное расписание должно корректно восстанавливаться.

## Decision Drivers

* **Простота интерфейса:** Сокращение вариантов выбора до 3 фундаментальных (как у салона, свое время, выходной).
* **Гибкость настроек:** Поддержка ввода произвольного времени работы администратором вручную.
* **Предсказуемость бизнес-логики:** Неактивный мастер не должен иметь рабочих часов, но его расписание не должно безвозвратно удаляться из базы данных.

## Proposed Changes

1. **Инвариант I15 (Деактивация мастера):** Добавлен в `MATH_MODEL.md`. При `isActive === false` все дни мастера считаются выходными (`null`), при активации возвращается реальное расписание.
2. **Отображение неактивного мастера:**
   - В карточке мастера (`adm_v_m`), если мастер неактивен, для всех дней недели выводится «Выходной».
   - При попытке изменить расписание неактивного мастера выводится предупреждение: «⚠️ Нельзя редактировать расписание неактивного мастера. Сначала активируйте его.» с кнопкой возврата в карточку.
3. **Три варианта настройки расписания:**
   - На шаге настройки дня недели (`adm_wh_d`) выводить только три кнопки:
     1. `🏪 Как у салона (10:00 - 21:00)` -> сохраняет `10:00 - 21:00`.
     2. `✍️ Свое время` -> переводит в текстовый ввод произвольного диапазона.
     3. `💤 Выходной` -> сохраняет `null` (выходной).
4. **Ввод своего времени:**
   - Создать шаг `admin_edit_master_wh_custom` и сохранять в сессии `editingDay` и `selectedMasterId`.
   - Запрашивать ввод в формате `ЧЧ:ММ-ЧЧ:ММ` (например, `12:00-19:00`), валидировать по регулярному выражению и проверять логику времени (начало раньше окончания).
   - При успешном вводе обновлять `workingHours` мастера для этого дня и возвращать администратора к списку дней недели с сообщением об успехе.

## Consequences

* **Положительные:** Администратору проще настраивать расписание. Поддерживается абсолютно любое время работы мастеров (не только 3 фиксированных шаблона). Деактивация мастера безопасно скрывает его расписание, но сохраняет настройки в БД.
* **Отрицательные:** Требуется дополнительный шаг текстового ввода и валидация формата времени.
