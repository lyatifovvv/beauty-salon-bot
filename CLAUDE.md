# CLAUDE.md — правила работы Claude Code в этом проекте

Этот файл читает Claude в начале каждой сессии. Держи коротким.

---

## ⛔ ГЛАВНОЕ ПРАВИЛО

**`docs/core/MATH_MODEL.md` — единственный источник правды для проекта.**

Любое изменение поведения проекта идёт строго в порядке:
1. `@reviewer хочу <изменение>` — обновляет мат-модель, создаёт ADR
2. Пользователь утверждает
3. **Только потом** обновляется код

Нельзя: менять код без обновления мат-модели, обходить @reviewer «потому что мелочь», писать ADR постфактум.

Подробности: @docs/core/WORKFLOW_RULES.md

## Пользователь

Это владелец бизнеса (например, владелица бьюти-салона, 50 лет), **не программист**.

Общайся:
- На русском, на «ты»
- Простыми словами, без жаргона
- Если используешь термин — переведи в скобках
- Когда что-то ломается → передай `@friendly-troubleshooter`, **сначала «не паникуй»**
- Один вопрос за раз через AskUserQuestion если можешь

## Жёсткие правила

**Always (всегда):**
- Запускай линтер и тесты перед коммитом
- Используй термины из `docs/core/GLOSSARY.md`
- Миграции БД только через инструмент стека, не ALTER в коде
- Логируй опасные операции (удаления, изменения цен, отмены)
- При самопроверке ссылайся на `§N.M` мат-модели

**Ask first (спроси сначала):**
- Добавление новой зависимости
- Изменение схемы БД
- Ломающее изменение публичного API
- Изменение мат-модели — только через `@reviewer`

**Never (никогда):**
- Коммитить `.env`, секреты, токены
- Удалять failing-тест без разрешения
- Менять инварианты `MATH_MODEL.md` без ADR
- Хранить пароли в открытом виде (только bcrypt cost ≥12 или argon2)
- `git push --force` в main
- Захардкоживать секреты (только через `process.env` / `os.getenv`)

## Subagents (используй проактивно)

- **`@design-engineer`** — любая UI/UX работа («сделай сайт/секцию/landing красиво»)
- **`@security-guard`** — перед каждым деплоем, при добавлении auth
- **`@friendly-troubleshooter`** — при любой ошибке или «не работает»
- **`@reviewer`** — для запросов на изменения проекта (всегда!) и финального ревью
